## 운영 방법론

단위 테스트의 **설계 → 작성 → 실행 및 커버리지 측정 → 실패 분석 및 수정** 전 과정을 닫힌 루프(Closed-loop)로 직접 수행한다.
(사용자가 "설계만" 또는 "실행만" 명시적으로 요청한 경우에는 해당 Phase만 수행한다.)

---

### Phase 1 — 대상 및 실행 환경 분석

1. **실행 환경 파악**
   - 프로젝트의 빌드/테스트 도구(`pytest`, `jest`, `vitest`, `go test`, `ctest`, `cargo test` 등)와 기존 테스트 디렉터리 구조를 확인한다.
2. **테스트 대상 식별 및 우선순위 결정**
   - 대상 함수/메서드/클래스의 입력(파라미터 타입·범위), 출력(반환값·예외·부수 효과), 외부 의존성(DB, 파일, 네트워크, 시간, 난수)을 파악한다.
   - 위험 기반 우선순위:
     - **높음**: 핵심 비즈니스 로직, 복잡한 조건 분기, 자주 변경되거나 버그 이력이 있는 코드
     - **중간**: 유틸리티 함수, 입력 검증 로직
     - **낮음**: 단순 getter/setter, 보일러플레이트

---

### Phase 2 — FIRST 원칙 및 블랙박스 테스트 케이스 설계

1. **FIRST 원칙 기반 격리 전략**
   - **F**ast (100ms 이하): DB·네트워크·파일 I/O는 Mock/Stub/Fake로 격리한다.
   - **I**ndependent (순서 독립): 테스트 간 공유 상태를 제거하고 `setUp`/`tearDown`으로 초기화한다.
   - **R**epeatable (재현성): 현재 시각, 난수, 외부 API 응답은 고정값(Seed/Stub)으로 제어한다.
   - **S**elf-validating (자동 판정): `print` 수동 확인 없이 명확한 Assert문으로 판정한다.
   - **T**imely: 변경된 공개 동작(Behavior)을 즉시 검증한다.

2. **블랙박스 설계 기법 적용**
   - **동등 분할 (EP)**: 유효 입력 그룹과 무효 입력 그룹(범위 초과, null/빈 값, 잘못된 타입)에서 대표값을 도출한다.
   - **경계값 분석 (BVA)**: 경계 `N`에 대해 `N-1`, `N`, `N+1`을 모두 포함한다.
   - **결정 테이블**: 복합 조건 분기가 있는 경우 조건 조합별 기대 결과를 열거한다.
   - **상태 전이**: 상태를 가지는 객체는 유효 전이와 무효 전이 시도를 모두 검증한다.

---

### Phase 3 — AAA 패턴으로 테스트 코드 작성

- 모든 테스트는 **Arrange(준비) → Act(단 하나의 실행) → Assert(검증)** 구조를 따른다.
- 구현 세부사항(private 변수, 내부 호출 순서)이 아닌 **공개된 동작과 결과**를 검증한다 (`engineering.md` 준수).
- 테스트 이름만으로 `[대상]_[조건]_[예상 결과]`를 알 수 있게 작성한다.

---

### Phase 4 — 단위 테스트 실행, 검증 및 커버리지 측정

작성한 테스트를 반드시 직접 실행하여 컴파일·런타임 오류와 통과 여부를 즉시 검증한다 (`accuracy.md` 준수).

```bash
# 언어별 실행 및 커버리지 측정 예시
# Python: pytest --cov=src --cov-report=term-missing
# JS/TS:  npm test -- --coverage
# Go:     go test ./... -coverprofile=coverage.out
# C/C++:  ctest --output-on-failure && gcovr
```

- **실패 발생 시 진단 및 조치**:
  - **테스트 코드 오류(Type B)**: 잘못된 Mock 설정·import·Assertion 오타는 즉시 테스트 코드를 수정해 재실행한다.
  - **프로덕션 구현 버그(Type A)**: 예상값과 실제값, 실패 라인을 명확히 기록하여 보고하거나(요청 범위에 포함된 경우) 근본 원인을 수정한다.
- **권장 커버리지 기준**: Line 80% 이상, Branch 70% 이상 (핵심 로직 기준).

```markdown
## 🧪 단위 테스트 리포트

### 분석 및 실행 요약
- **대상**: [파일/함수 목록]
- **실행 명령**: `[실행한 테스트 명령어]`
- **결과**: 전체 N개 (✅ 통과 N / ❌ 실패 N / ⏭️ 스킵 N)

### 작성·검증된 테스트 케이스
| ID | 대상 함수 | 기법 (EP/BVA/DT/ST) | 조건 | 결과 |
| :--- | :--- | :--- | :--- | :--- |
| TC-01 | `fn()` | BVA | 입력이 경계값 0일 때 | ✅ PASS |

### 커버리지 현황
| 지표 | 현재 | 목표 | 판정 |
| :--- | :--- | :--- | :--- |
| Line Coverage | N% | 80% | ✅/⚠️/🚨 |
| Branch Coverage | N% | 70% | ✅/⚠️/🚨 |

### ❌ 실패 원인 분석 및 미커버 영역 (해당 시)
- [실패 원인(구현 버그 vs 환경 문제) 또는 커버되지 않은 분기와 이유]
```
