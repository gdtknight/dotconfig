## 운영 방법론

코드베이스 원문을 직접 확인(`accuracy.md` 준수)하여 **사전 지식이 전혀 없는 신규 담당자가 Day 1에 프로젝트를 이해하고 로컬에서 실행할 수 있는 인수인계 가이드**를 작성한다.

---

## 작성 원칙 및 다이어그램 기준

1. **원문 근거 기반 작성 (`accuracy.md`)**:
   - 모든 디렉터리 역할, 진입점, 환경 변수, 실행 명령어, 포트 번호는 실제 설정 파일과 소스 코드(`파일:라인`)를 직접 열어 확인한 사실만 기술한다. 확인 불가한 운영 정보는 `미확인 (확인 방법: ...)`으로 명시한다.
2. **WHY 중심 설명**:
   - 단순 파일 나열이 아니라 "왜 이 구조로 나뉘어 있는가", "어디서부터 코드를 읽어야 하는가"를 설명한다.
3. **다이어그램 도구 선택 (Mermaid 기본, D2 선택)**:
   - **기본값 (Mermaid)**: 별도 외부 컨테이너 실행 없이 GitHub, IDE, Obsidian, 마크다운 뷰어에서 즉시 렌더링되는 `mermaid` 코드 블록(`flowchart`, `sequenceDiagram`, `classDiagram`, `erDiagram`)을 문서 내에 직접 삽입한다. (특수문자 포함 노드 라벨은 반드시 큰따옴표 `id["Label (Info)"]`로 감싼다.)
   - **선택값 (D2 + ELK SVG)**: 사용자가 명시적으로 D2/SVG 이미지 생성을 요청한 경우에만 `d2` CLI 또는 `docker run --rm -v "$(pwd):/data" terrastruct/d2 --layout elk`를 사용해 `docs/images/*.svg`를 생성한다.

## 실행 절차 (5 Phases)

### Phase 1 — 프로젝트 구조 및 빌드·실행 환경 스캔
- 패키지 매니저·빌드 설정(`package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `CMakeLists.txt`, `Makefile`, `Brewfile`, `docker-compose.yml` 등)과 진입점(`main`, `index`, `app`, `server`, `install.sh` 등)을 확인한다.
- 필수 환경 변수(`.env.example`, 설정 로더 코드)와 실제 로컬 실행·테스트 명령어를 파악한다.

### Phase 2 — C4 Model 기반 아키텍처 계층화
프로젝트 규모에 맞게 C4 Model을 적용해 시각화한다:
1. **Level 1 (System Context)**: 사용자, 대상 시스템, 외부 연동 시스템(DB, 외부 API, 인증 등) 간의 관계
2. **Level 2 (Container)**: 웹/앱, API 서버, 워커, DB, 캐시 등 실행 단위와 통신 프로토콜
3. **Level 3 (Component)**: 핵심 컨테이너 내부의 레이어·모듈 구조와 의존 방향
4. **Level 4 (Code — 핵심 모듈만 선택)**: 변경이 가장 잦거나 복잡한 핵심 도메인 클래스/구조체 관계

### Phase 3 — 핵심 유스케이스 실행 흐름 추적
- 시스템을 대표하는 핵심 유스케이스 2~3개를 선정하여 진입점(`파일:라인`)부터 비즈니스 로직, 저장소 호출까지의 흐름을 `sequenceDiagram` 또는 `flowchart`로 작성한다.

### Phase 4 — 데이터 모델 및 주요 설계 결정(ADR) 정리
- 핵심 엔티티/스키마/상태 전이 조건을 표와 `erDiagram`으로 정리한다.
- 코드베이스와 커밋 히스토리에서 확인된 아키텍처 설계 결정(ADR: 컨텍스트 → 결정 → 근거 및 트레이드오프)과 알려진 기술 부채/주의사항을 기록한다.

### Phase 5 — 가이드 문서 생성 및 자체 검증
- `docs/PROJECT_GUIDE.md`(또는 사용자가 지정한 경로)에 아래 표준 목차로 문서를 작성하고, 문서 내 모든 파일 경로·라인 번호·명령어가 실제 코드베이스와 일치하는지 최종 대조한다.

---

## 표준 문서 목차 (`docs/PROJECT_GUIDE.md`)

1. **프로젝트 개요** (한 줄 요약, 배경 및 목적, 핵심 기능)
2. **빠른 시작 (Quick Start)** (사전 요구사항, 설치·환경설정·실행·테스트 단계별 명령어와 기대 출력)
3. **시스템 아키텍처 (C4 Model)** (Context → Container → Component 다이어그램 및 디렉터리 구조)
4. **핵심 코드 흐름** (주요 유스케이스 시퀀스 다이어그램 및 진입점 `파일:라인`)
5. **데이터 모델 및 상태 전이** (ERD / 핵심 설정 스키마 및 상태값 정의)
6. **환경 설정 및 외부 의존성** (환경 변수 표, 외부 연동 서비스)
7. **주요 설계 결정 (ADR) 및 주의사항** (설계 배경, 기술 부채, 수정 시 주의할 레거시 구간)
8. **도메인 용어 사전**

```markdown
## 📚 프로젝트 가이드 작성 리포트

### 포함 섹션 및 시각화 현황
| 섹션 | 다이어그램 유형 | 상태 |
| :--- | :--- | :--- |
| 시스템 아키텍처 (C4) | Mermaid `flowchart` | ✅ 완료 |
| 핵심 코드 흐름 | Mermaid `sequenceDiagram` | ✅ 완료 |
| 데이터 모델 | Mermaid `erDiagram` / 표 | ✅ 완료 |

### 수동 확인 권장 항목 (해당 시)
- [코드만으로 확인 불가하여 `미확인` 표시한 외부 계정/인프라/히스토리 항목]
```
