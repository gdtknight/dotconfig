## 운영 방법론

통합 테스트를 실행하고 인터페이스 경계에서의 동작을 검증한다. 4개 Phase를 순서대로 수행한다.

---

### Phase 1 — 실행 전 환경 검증

통합 테스트는 단위 테스트보다 환경 의존성이 높다. 실행 전 반드시 확인한다.

**1-1. 의존 서비스 상태 확인**
```bash
# 실제 외부 서비스가 필요한 경우
# DB 연결 테스트
# API 서버 헬스체크
# 메시지 큐 연결 확인

# Mock 서버를 사용하는 경우
# Mock 서버 기동 여부 확인
# Stub 데이터 준비 여부 확인
```

**1-2. 테스트 격리 확인**
- 각 통합 테스트가 독립적으로 실행될 수 있는가?
- 테스트 간 공유 상태(DB 데이터, 파일, 전역 설정)가 초기화되는가?
- 테스트 실행 순서에 따라 결과가 달라지지 않는가?

**1-3. 통합 전략 파악**
기존 테스트가 Top-Down / Bottom-Up / Sandwich 중 어느 방식인지 파악하고, 실행 순서를 결정한다.

---

### Phase 2 — 테스트 실행 및 인터페이스 추적

**2-1. 단계적 실행**
통합 전략에 따라 단계별로 실행한다.
```bash
# Bottom-Up 예시: 하위 모듈부터 순서대로
# Step 1: DB 레이어 통합 테스트
# Step 2: 비즈니스 로직 + DB 통합 테스트
# Step 3: API 레이어 + 비즈니스 로직 + DB 통합 테스트

# 각 단계 실패 시 다음 단계로 진행하지 않는다
# 실패 지점을 명확히 격리하기 위해
```

**2-2. 데이터 흐름 추적**
각 통합 지점에서 데이터가 올바르게 전달되는지 확인한다.
```
추적 항목:
- 입력 데이터가 변환 없이 또는 정확히 변환되어 전달되는가?
- 직렬화/역직렬화 과정에서 데이터 손실이 없는가?
- 문자 인코딩, 타입 변환, 날짜/시간 형식이 일관되는가?
- NULL/빈값이 경계에서 올바르게 처리되는가?
```

**2-3. 인터페이스 계약 검증**
각 모듈 경계에서 계약 준수 여부를 확인한다.
```
API 계약 검증:
  - 요청 스키마: 필수 필드 존재, 타입 일치, 형식 준수
  - 응답 스키마: 예상 필드 존재, 타입 일치, 상태코드 정확
  - 에러 응답: 에러 형식 일관성, 에러 코드 정확성

함수 계약 검증:
  - 사전 조건(precondition)이 지켜질 때 올바른 결과 반환
  - 사전 조건 위반 시 명확한 에러/예외 발생
  - 함수 호출 후 시스템 상태(사후 조건) 검증
```

---

### Phase 3 — 장애 지점 격리 분석

통합 테스트 실패 시 어느 모듈 경계에서 실패했는지 정확히 격리한다.

**3-1. 실패 경계 결정 트리**
```
실패 발생
  ├── 입력값이 인터페이스에 도달하지 않음
  │     → 호출 모듈(Consumer) 문제
  ├── 인터페이스 계약 불일치
  │     → 계약 위반 — 양쪽 모듈 검토 필요
  ├── 제공 모듈(Provider)이 잘못된 결과 반환
  │     → 제공 모듈 내부 버그
  └── 결과를 수신 모듈이 잘못 처리
        → 수신 모듈(Consumer) 문제
```

**3-2. 격리 기법**
```bash
# 의심 모듈을 Stub으로 교체하여 나머지가 정상인지 확인
# 통합 지점 직전/직후 로그 삽입으로 데이터 스냅샷 비교
# 단위 테스트로 해당 모듈 단독 동작 검증
```

**3-3. 환경 원인 vs 코드 원인 구분**
```
환경 원인 징후:
  - 동일 코드가 환경에 따라 다른 결과
  - 타임아웃, 연결 실패, 권한 오류
  - 특정 데이터 상태에서만 실패

코드 원인 징후:
  - 재현 가능한 실패
  - 특정 입력 조합에서 항상 실패
  - 스택 트레이스가 코드 라인을 지목
```

---

### Phase 4 — 비기능 검증

**4-1. 성능 경계 확인**
```bash
# 응답 시간이 SLA 내인가?
# 타임아웃 설정이 적절한가?
# 대용량 데이터 처리 시 메모리 사용량이 적절한가?
```

**4-2. 에러 처리 및 복구**
- 외부 의존성 장애 시 graceful degradation이 작동하는가?
- 재시도(retry) 로직이 적절히 동작하는가?
- 실패한 트랜잭션이 완전히 롤백되는가?
- 리소스(연결, 파일 핸들, 메모리)가 오류 발생 후 정리되는가?

**4-3. 멱등성(Idempotency) 검증**
같은 요청을 여러 번 실행했을 때 의도한 결과만 발생하는가?
