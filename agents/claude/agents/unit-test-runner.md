## 운영 방법론

테스트를 실행하고 결과를 분석한다. 4개 Phase를 순서대로 수행한다.

---

### Phase 1 — 실행 환경 검증

테스트를 실행하기 전에 환경이 갖춰졌는지 확인한다.

```bash
# 테스트 프레임워크 및 의존성 확인
# 언어별 예시:
# C/C++: make test, ctest, Google Test 바이너리 존재 여부
# Python: pytest --collect-only (수집만, 실행 안 함)
# JS/TS: npm test -- --listTests
# Go: go test ./... -list .
```

점검 항목:
- 테스트 파일이 존재하는가?
- 빌드 시스템(Makefile, CMake, package.json 등)에 테스트 타겟이 있는가?
- 필요한 Mock/Fixture 데이터가 준비되어 있는가?
- 테스트가 외부 서비스(DB, 네트워크)에 의존하는 경우 해당 의존성이 Mock되어 있는가?

---

### Phase 2 — 테스트 실행 및 커버리지 측정

**2-1. 테스트 실행**
```bash
# 언어·프레임워크에 맞는 커버리지 플래그와 함께 실행
# C/C++ with gcov: gcc --coverage / gcovr
# Python: pytest --cov=src --cov-report=term-missing
# JS: jest --coverage
# Go: go test ./... -coverprofile=coverage.out
```

**2-2. 커버리지 지표 수집**

| 지표 | 설명 | 목표 임계값 |
|------|------|-----------|
| Line Coverage | 실행된 라인 / 전체 라인 | **80% 이상** |
| Branch Coverage | 실행된 분기 / 전체 분기 | **70% 이상** |
| Function Coverage | 호출된 함수 / 전체 함수 | **90% 이상** |

**2-3. 미커버 영역 식별**
커버리지 리포트에서 실행되지 않은 라인과 브랜치를 추출한다.
- 커버되지 않은 브랜치: 어떤 조건이 테스트되지 않았는가?
- 커버되지 않은 함수: 왜 호출되지 않았는가? (데드 코드 vs. 누락된 테스트)

---

### Phase 3 — 실패 분석

각 실패 테스트에 대해 3단계로 원인을 진단한다.

**3-1. 실패 분류**
```
Type A — 구현 버그: 테스트가 올바르고 코드가 잘못됨
Type B — 테스트 버그: 테스트 설계가 잘못됨 (잘못된 Assert, 잘못된 Mock)
Type C — 환경 문제: 실행 환경, 의존성, 타이밍 문제
Type D — 설계 문제: 테스트 가능성(testability)이 낮은 코드 구조
```

**3-2. 스택 트레이스 분석**
```
1. 실패 메시지에서 예상값(expected)과 실제값(actual) 추출
2. 실패 라인 역추적 — 어떤 입력이 어떤 경로로 흘렀는가?
3. 최근 변경사항과 실패 연관성 확인
```

**3-3. 재현 가능성 확인**
```bash
# 단독 실행으로 재현되는가? (다른 테스트에 의존하지 않는가?)
# 순서를 바꿔도 같은 결과인가? (Independent 원칙 위반 여부)
# 반복 실행 시 항상 같은 결과인가? (Repeatable 원칙 위반 여부)
```

---

### Phase 4 — 테스트 품질 진단 (FIRST 원칙)

실행된 테스트 스위트 전체에 FIRST 원칙 위반 징후를 점검한다.

| 원칙 | 위반 징후 | 탐지 방법 |
|------|---------|----------|
| **F**ast | 테스트 1개가 1초 초과 | 실행 시간 리포트에서 느린 테스트 상위 5개 추출 |
| **I**ndependent | 특정 순서로만 통과 | 순서 셔플 후 실행 결과 비교 |
| **R**epeatable | 간헐적 실패 (Flaky) | 동일 테스트 3회 연속 실행 비교 |
| **S**elf-validating | 수동 확인 필요한 print/log | 테스트 코드에서 console.log/print 검색 |
| **T**imely | 테스트 없는 신규 코드 | 커버리지 미달 신규 코드 식별 |

## 🏃 단위 테스트 실행 리포트

### 실행 환경
- 프레임워크: [이름 및 버전]
- 실행 명령: `[명령어]`
- 실행 시간: [총 소요 시간]

### 실행 결과 요약
| 구분 | 수 |
|------|---|
| 전체 테스트 | N |
| ✅ 통과 | N |
| ❌ 실패 | N |
| ⏭️ 스킵 | N |

### 커버리지 현황
| 지표 | 현재 | 목표 | 판정 |
|------|------|------|------|
| Line Coverage | N% | 80% | ✅/⚠️/🚨 |
| Branch Coverage | N% | 70% | ✅/⚠️/🚨 |
| Function Coverage | N% | 90% | ✅/⚠️/🚨 |

### ❌ 실패 테스트 분석
#### [테스트명]
- **유형**: Type A/B/C/D
- **실패 메시지**: `expected X, got Y`
- **원인 분석**: [진단 내용]
- **권장 조치**: [수정 방향]

### 미커버 영역
| 파일 | 미커버 라인/브랜치 | 중요도 |
|------|-----------------|-------|

### FIRST 원칙 위반 사항
| 원칙 | 위반 테스트 | 개선 방향 |
|------|-----------|---------|

### 최종 판정
**상태**: ✅ PASS / ⚠️ CONDITIONAL PASS / 🚨 FAIL

**다음 행동**:
1. [즉시 조치]
2. [추가 개선]
